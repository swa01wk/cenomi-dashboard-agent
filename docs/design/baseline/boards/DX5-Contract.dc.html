DX5 · Generative UI contract

Design contract for GENERATIVE_UI.md, AGUI_INTEGRATION.md and API_CONTRACTS.md, revised after the DX5 review. DX5 is approved; the refinements DXD-55…62 are folded in below. The interactive board demonstrates and tests every rule.

1 · The result is authoritative

  • Tools produce analysis_result.v1: rows, facts (raw and formatted), metric, filters, scope, dimensions, dataset, coverage.
  • Every derived fact carries a verified calculation record (DXD-55). Neither the LLM nor the renderer derives business values.
  • Components read values from the result, never from the payload.

2 · The payload only chooses how

  • cenomi.presentation.v1 names a registered component, a resultRef, a title and encodings.
  • The agent picks among allowed representations through a bounded policy (DXD-51); the user can switch with View as.
  • No code, markup, links or values in the payload.

3 · Checks before anything renders

  • Result checks: resolve, authorize against grants, verify calculations.
  • Presentation checks: schema, registry, grounding, envelope, limits, safety.
  • Only a presentation failure on a good result falls back to the table (DXD-57).

Validation pipeline (DXD-47, amended by DXD-57)

StepChecks
R1 · Result resolvesresultRef names a validated result of this run (or a stored one being resumed).
R2 · Authorization (grants vs scope, dimensions, records)The viewer’s current grants cover every region, mall and lease in the result scope and dimensions, and every drilldown record. Re-run on resume. Never a label comparison.
R3 · Calculations verifiedEvery derived fact has a verified calculation record; the verifier recomputes it from its operands.
P1 · Schemacenomi.presentation.v1; required fields; no unknown fields (a payload cannot carry its own values, data or rows).
P2 · RegistryComponent is in the closed registry and can show this result’s shape; encodings name real dimensions.
P3 · GroundingText uses fact tokens only; every token is a fact of the result.
P4 · EnvelopeAny envelope field present equals the result’s envelope (class, dataset, coverage, scope).
P5 · LimitsRows per component, title length, payload ≤ 64 KB.
P6 · SafetyNo markup, script, links or forbidden keys in any string.

Authorization by grants (DXD-56)

  • Viewers carry grants: regions (admin all, regional manager Central), or leases (tenant T-31206, lease-level results only).
  • Each result carries its access scope: level, regions, malls, leases. Records are checked one by one on drilldown.
  • A result partly outside grants is withheld, never filtered by the renderer: a narrower question is a new query.
  • Stored results are revalidated on resume; error messages never name out-of-grant entities.

Representation policy (DXD-51)

RuleInputEffect
P1RegistryKeep only kinds that can show the result’s shape; drop Text without verified statements.
P2IntentOrder by the user’s intent: ranking → bar, headline → card, trend → line, exact values → table, composition → treemap, concentration → heatmap, conversion → funnel.
P3Data and dimensionsFewer than three time points removes the line; more rows than the width limit keeps the bar as a disclosed top-N with the table holding every row.
P4Display spaceTreemap below 400 px → ranked list; a heatmap with more than four columns at ≤ 360 px → table first.
P5AccessibilityA screen-reader preference puts the table first; charts stay under View as. Every kind has text values, names and states regardless.
P6BudgetPanel 3, workspace 6 generated components; extra supporting information through Open in workspace and the inspector (DXD-54).

Subsets, pages and samples are always disclosed (DXD-59)

KindWhenDisclosure
CompleteEvery row of the result is shown.No line; declaration kind “complete”.
Top-NA chart at its width limit (bar: workspace 15, panel 10, canvas/phone 8).“Subset · top 10 of 25 malls by highest value. The other 15 are in the table view; totals cover all rows.”
PageA table over its page size (workspace 25, panel 10, canvas/phone 8).“Page 1 of 3 · rows 1–10 of 25. Totals cover all rows.” with Previous / Next.

Each chart and table declares data-subset: kind, keys shown, total rows and order. The invariance check verifies the declaration against the result.

Continuity (DXD-60)

ActionGuarantee
Switch representation (View as)Same componentId, resultRef and selection key; envelope identical; selection shown on marks or as a selection note on kinds without marks.
Move panel ↔ workspaceComponent instance moves with its id, selection and envelope; layout changes per size class only.
ExpandDialog over the page with the same instance; Escape returns focus; nothing re-queried.
Resume a threadRehydrate {componentId, resultRef, selection} and re-run R1–R3 with current grants. If authorization fails the component is withheld and the stored selection is not restored.
FallbackKeeps componentId and selection keys; marks become table rows.
